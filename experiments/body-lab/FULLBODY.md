# 全身肌骨模型与验证范围

全身实验台在本机使用 MS-Human-700 派生的 v5 模型，覆盖头颈、分节躯干、胸廓、双臂、详细双手与双腿。模型有 249 个标量关节、207 个独立坐标。**740 个肌腱单元**共同参与每帧配力，输出张力、激活、关节力矩、外部支撑和适用的哑铃接触力。手指另有 **24 个被动参考坐标**用于核对参考力矩。显示侧的 460 个肌肉和跟腱表面有独立的图谱映射，不能按表面数推断肌腱单元数。

当前 v5 保留肩手组合 XML，用独立 manifest 声明两项手部修正。指深屈肌对左右小指掌指、近侧指间、远侧指间关节采用 Franko 等人表 2 的实测力臂拟合，两侧共六个屈曲轴。中指和其他手指沿用原模型路径几何。双侧食指至小指的八个指浅屈肌（FDS）单元将被动肌纤维和肌腱串联，两者承受相同张力，各自伸长之和为总伸长。肌腱曲线沿用 OpenSim 4.6 Thelen2003Muscle 的默认参数，在最大等长肌力下取 0.04 应变。这项参数是模型默认值。右侧正、负腕角对照的四段动作已通过 148/148 个采样帧，同版全身数值报告与正式网页报告均通过，固定动作库的 11 项共 803 个采样帧。群体单关节测量向双侧模型及联合动作的迁移属于建模假设。[OpenSim 4.6 参数说明](https://github.com/opensim-org/opensim-core/blob/4.6/OpenSim/Actuators/Thelen2003Muscle.h#L110-L114) · [默认值与实现](https://github.com/opensim-org/opensim-core/blob/4.6/OpenSim/Actuators/Thelen2003Muscle.cpp#L165-L171)

手指与哑铃使用接触代理及摩擦模型，人体逐肌张力、软骨压力、全部韧带力及软组织碰撞仍超出验证范围。[v5 模型声明](candidates/runtime/expanded-motion-repair-v5-manifest.json) · [来源与许可](ASSET_ATTRIBUTION.md) · [论文与表 2](https://pmc.ncbi.nlm.nih.gov/articles/PMC3124620/)

## 本机启动

正式版使用标签 `v1.1.0` 和同版 `release-assets.json`。从仓库根目录按[发行资源说明](RELEASE_ASSETS.md)安装四份资源。Windows 使用 Python 3.13 和仓库锁定的 MuJoCo、NumPy、SciPy 依赖。

```powershell
python -m venv .venv-fullbody
& ./.venv-fullbody/Scripts/python.exe -m pip install -r experiments/body-lab/candidates/runtime/requirements-lock.txt
& ./.venv-fullbody/Scripts/python.exe -B -X utf8 experiments/body-lab/setup_release_assets.py --manifest experiments/body-lab/release-assets.json --check
& ./.venv-fullbody/Scripts/python.exe -B -X utf8 experiments/body-lab/setup_release_assets.py --manifest experiments/body-lab/release-assets.json --download
& ./.venv-fullbody/Scripts/python.exe -X utf8 experiments/elbow-lab/server.py --port 4192
```

服务启动后打开[全身实验台](http://127.0.0.1:4192/experiments/body-lab/)。同一服务和端口也可打开[右臂页](http://127.0.0.1:4192/experiments/elbow-lab/)。原生工作进程默认使用仓库的 `.venv-fullbody`，也可用 `BODYVISTA_NATIVE_PYTHON` 指向已安装锁定依赖的解释器。GitHub Pages 仅托管静态图谱。

## 固定动作与自定义动作

自定义示例提供右手旋转、屈曲并握拳（50 帧）及左手旋转并松开（52 帧）。下载 JSON 后从“动作文件 → 导入”打开，再点击“计算受力”。这两份文件只存场景输入，力值由当前模型求解。[右手示例](examples/custom_right_rotate_bend_make_fist.json) · [左手示例](examples/custom_left_open_while_rotating.json)

在左侧“动作库”选择案例，画面停在首帧，再按“播放”检查人体、时间与受力。固定库含七个空手案例、四个哑铃案例，共 803 个采样帧，均与同版模型、计算指纹和正式网页缓存验收匹配。每个案例固定姿势、时长、负重与支撑，其结果在磁盘保留，刷新后点击同一案例直接读取。模型版本或文件内容不匹配时，页面提示重新验证。修改姿势、支撑或器械后，点击“计算受力”生成新结果。

| 动作 | 指定运动 | 时长／预检采样帧 |
|---|---|---:|
| 右肘缓慢屈伸 | 肘20°→90°，保持后返回 | 5秒／61帧 |
| 空手抬臂与屈肘 | 肩抬举35°并屈肘90°，保持后返回 | 5秒／61帧 |
| 头颈小幅转动 | 轴向转动10°并屈伸5°，保持后返回 | 5秒／61帧 |
| 右拇指缓慢屈伸 | 腕掌10°、掌指25°、指间20°，保持后返回 | 6秒／73帧 |
| 右手四指张开合拢 | 四个掌指外展坐标各到10°，保持后返回 | 6秒／73帧 |
| 屈膝位小幅内外旋 | 髋60°、膝90°下，外旋10°→内旋10°→返回 | 5秒／61帧 |
| 支撑下右膝伸屈 | 双髋70°、双膝90°起始，右膝伸至50°后返回 | 6秒／73帧 |
| 右手2 kg哑铃弯举 | 右肘0°→90°，保持后返回 | 7秒／85帧 |
| 左手1 kg哑铃屈伸 | 左肘15°→70°，保持后返回 | 7秒／85帧 |
| 双哑铃同步屈肘 | 双手各1 kg、总质量2 kg，双肘20°→70°后返回 | 7秒／85帧 |
| 右手0.5 kg哑铃小幅转前臂 | 肘保持60°，前臂旋转坐标−10°→10°后返回 | 7秒／85帧 |

四个哑铃案例使用右手 2 kg、左手 1 kg、双手各 1 kg 和右手 0.5 kg，均有明确的骨盆外部支撑。支撑力及骨盆广义支撑力矩单列。缓存只代表该版本的已验采样帧；某一个合法姿势能维持静止也不保证整段插值动作可行。`motion-cache/catalog.json` 指向具名的 gzip，包含实际姿势、740 个肌腱张力及激活、关节力矩、支撑与适用的器械接触力。每次选择都核对模型／计算身份与文件哈希，失败时停用旧力值。 [缓存安装和核验](RELEASE_ASSETS.md)

本机入口为 [全身动作实验台](http://127.0.0.1:4192/experiments/body-lab/?demo=lift)。页面左上角的区域选择器可放大全身、头颈、躯干、胸廓、左右手臂、手指、腿和足。关节点与名称默认收起，鼠标靠近身体时显示附近控制点，并检查前后遮挡；键盘 Tab 聚焦也会显示。点击圆点或名称选择关节，再拖对应运动轴的彩色环旋转本级关节，下游随动、上游锁定。摆好后点击“确认当前姿势为关键帧”，再摆下一帧并输入两帧间隔；拖空白处旋转视角，滚轮缩放。点击可见肌肉会在画布显示名称卡，保留解剖表面名称与相应计算单元的区别；点击空白处关闭。

自定义动作时，可先点击“检查当前姿势受力”：按所示姿势、当前负重与支撑，调用同一求解器检查静止保持，核对全部740个肌腱及适用的支撑、握持条件。检查不改变原有关键帧，也不启用整段力值；改变所示姿势或条件会清除旧检查结论。首尾姿势各自可行，仍不保证插值运动全程可行，需要继续点击“计算受力”。

整段失败时，自动打开右侧“受力结果”，显示首个未通过时间、所在关键帧或过渡段、主要未平衡坐标及支撑、接触等具体原因。可用“查看首个未通过姿势”定位，用“编辑姿势”返回相关关键帧；没有外部支撑时可明确选择“改用骨盆支撑”，随后重新计算。新动作沿用当前支撑与负重。带负重“回到站姿”会保留对应持物手的手指姿势；手指与器械尚无有效握持时，不能确认或替换关键帧，需重新握持。

旧 v3 的肩部和手部诊断记录了部分外形合法但配力失败的姿势。该版本的同条件复算中，单轴屈肘、抬肩、屈腕、屈髋和屈膝各25帧通过；肩方向与抬举同时变化有5/25帧失败，放慢后仍有失败；食指近端指间关节的小幅屈曲也存在不可行区间。肩部失败与源模型已有的被动关节参数及可用肌肉力矩有关，手部失败涉及多关节共同平衡，不能解释为真人无法做这些动作。这些结果属于旧 v3，v5 的当前结论以同版正式验证报告为准。这些抽查不是任意动作可用性的证明；一帧不通过时仍停用整段有效力值。

可编辑入口已整理为96个，均使用计算模型的原生关节锚点。原114项骨段信息仍保留，16个无独立运动的骨段和两个重复腕入口不再生成控制点；204个独立转角与3个骨盆平移参数仍可访问。相关的肘/前臂、腕/前臂、踝/距下和拇指两段控制可直接从关节卡切换。选中关节后，界面同时列出实际支持的各个运动轴、角度和微调按钮，并在关节周围画出对应的彩色旋转环。默认拖同色环绕该原生轴转动，不要求先转相机；环接近侧向而投影变扁时，使用明确的直线拖动把手或微调按钮，也可主动点击“对准旋转面”。鼠标输入只决定已选轴的角度，不再调整整条上游链或自由深度来追目标。

当前模型的髋有屈伸、内收外展和内外旋三个独立坐标；腕有屈伸和桡尺偏两个。肘的屈伸与前臂旋前旋后分属尺骨、桡骨控制点；双膝可分别调整屈伸与内外旋。新增膝旋转相对原屈伸耦合轨迹计算，正值内旋、负值外旋；伸直时锁定额外旋转，0–30°屈膝逐渐开放到内旋25°、外旋35°，此后不再放宽。界面实时显示当前范围，已经旋转时伸膝超限会被拒绝，需要先减小旋转；范围属于具名的教学工程包络，依据及公式见[约束说明](ANATOMY_CONSTRAINTS.md)。肩采用抬举方向、抬举角度和内外旋三个参数，垂臂时部分原生轴重合，可先定方向再抬臂。腕锁住前臂，膝锁住大腿；肩复合允许锁骨、肩胛、肱骨联动，锁住胸廓。严格视平面模式仍可选，但只能接受本级坐标实际能完成的平面旋转。

原屈伸轨迹、源范围及其余耦合仍生效，并加入屈膝相关旋转包络、联合极端组合与主要身体部位防穿插检查，见[约束依据与范围](ANATOMY_CONSTRAINTS.md)。这些工程保护不代表已经重建人体完整可达域或软组织接触，也不提供假想韧带反力。历史无效姿势会保留并显示原因，需修复后才能确认为新关键帧；包含无效姿势的动作不提供有效肌力。刷新恢复关键帧和草稿，已有动作不被 URL 演示参数覆盖。v3 兼容旧 v2 姿势，新增膝旋转补0，旧存储副本保留；计算结果须按新版重算。

把哑铃拖到可见手掌附近，或点击“握住选定器械”，会调整所选手的手指并同步当前动作的关键帧；手腕与上肢保持原位。在左侧“器械与地面”输入总质量，可选择右手、左手或双手各一只，双哑铃按总质量均分。器械位置、方向和尺寸与后端接触几何一致，可撤销本次握持。张手或握持不相容不会再获得有效持物肌力。杠铃功能已移除：旧杠铃动作在导入或恢复时先保留浏览器备份，再保留姿势和时间、清零负重，并提示重新选择哑铃；旧力值不复用。后端不再接受杠铃计算请求。

手部胶囊与握把的单向接触、摩擦、指关节肌肉以及器械平动/转动惯性在同一次配力中求解，负重通过真实接触指骨进入全身。几何贴合与承重通过分别显示；先握住再计算，不能只凭画面闭合认定可以承重。详细假设、来源、验证与未实现项见[握持说明](GRASP.md)。支撑仍必须指定：骨盆支架单独报告辅助作用力，足底模式检查单向承重、摩擦、足滑和穿地。

“地面”按钮开启后显示世界高度0米的地面，并切换到足底支撑；关闭时恢复当前动作先前选择的非足底支撑，若在有地面时已主动选择骨盆支架或无支撑，则保留该选择。直接载入足底支撑动作时，没有声明先前支撑，移除地面后使用无外部支撑，不继承另一动作的支架。人体重力始终存在，地面开关不会开启、关闭或重复加入重力。模型人体质量约59.611 kg，对应重力约584.784 N；正常站姿的足底支撑合力与之相等。无地面且无外部支撑时，静止悬空会报告整体未平衡力；这是对指定动作的检验，尚不自动生成落体运动。有地面时检查全部132个骨骼网格与足底站点，穿地则保留动作并停用肌力；没有皮肤、手掌、膝盖或躯干地面支撑求解。

点击“计算受力”后，可按区域或名称选择肌束查看张力；表格分别显示净需求、肌肉合计、关节止挡和未平衡量。此按钮从当前关键帧和条件重新求解；左侧“动作库”的固定案例按钮读取已核验的完整结果。两条路径均使用来源模型的质量、附着点、最大力等参数，并非完全不需要已有生物力学知识。

“观察肌束”仅列出整段有效动作中张力最大值与最小值之差大于0.01 N的单元，按变化幅度从大到小排序。始终为零、恒定非零和缺少完整张力数据的单元不列入；仍可按区域和名称进一步筛选。列表在新结果载入时更新，不随回放每一帧跳动；修改动作后清空，未计算、仅预览或筛选无匹配时禁用并说明原因。点击模型也不能把不符合条件的单元加入列表。全部740个肌腱仍参与配力，筛选不改变或删减保存的力数据。

肌肉显示默认为项目原有的解剖表面：458 个肌肉网格及 2 条原图谱跟腱保留约 160 万个三角形，按计算骨架各骨段配准并随姿势变形；可切换到原计算肌腱路径观察力学线路。点击表面可查看解剖名称及其与计算单元的对应关系。当前 226 个表面映射到736个计算单元，并按原生肌腱附着、绕行骨段及相连骨链限定随动范围；一块表面关联多条肌束时，着色与卡片报告“关联肌束最大张力”，不是整块肌肉合力。其余表面标为“未建立定量映射”，不会因为有外形动画就显示力值。面部等表面的可见性也不代表相应力学已包含。

表面动画是基于源骨架与附着范围的显示近似，保留原网格并对肌腹长度变化作横向补偿。双侧股四头肌、缝匠肌、股薄肌共12个表面改用沿实际骨链分区的平滑蒙皮，避免把宽贴骨区域当作两个虚拟端点整体拉伸；股肌近骨区域以原股骨表面辅助局部配准，窄端参考对应原生肌腱端点登记，逐项写入 `attachmentBinding`。另外，双侧腓肠肌内外侧头与比目鱼肌共6个肌肉表面使用与原跟腱一致的配准和权重场，肌腹远端不再直接绑定跟骨形成长杠杆；腓肠肌近端归股骨，跟腱末端归跟骨。跟腱与肌腹相邻区停用径向膨胀，保持源网格接口连续；跟腱单独计数和点选，不新增肌肉执行单元或独立张力。合计18个肌肉表面与2条跟腱具有专门绑定。这些显示修正不改变计算模型的附着点或肌力参数；不能解释成逐肌精确配准、软组织碰撞或有限元求解。

全身逐项审计又检查了中立位、代表运动姿势、骨链和权重。22个长肌使用两端随骨的连续曲线运输原网格，避免屈肘时出现S折或腕端回折；手内在肌采用共同的保形静止配准，避免尚未运动就被不同骨段配准揉皱。颈部、胸背、髋及足部重新限定随骨范围；源斜方肌4个上下部标签与实际形状位置相反，在实验清单中保留原标签与校正理由。双侧锁骨部三角肌改沿原生DELT1路径运输源网格截面，改善大幅抬肩时向肱骨头下方回折；路径与截面数据由CPU拾取和GPU显示共用。双侧臀大、中、小肌及髂肌另核对宽附着区域随骨权重。小收肌、胸大肌锁骨部、股薄肌、髂肌远端和斜方肌横部仍有未关闭显示问题。这些图谱显示范围应与实际力学覆盖分别理解。

源网格、哈希和逐项署名记录在 `atlas-muscles.json`。参考静止帧与名称映射保留v2来源，新清单单独声明v3兼容性，不把旧参考帧冒称新版实测。`registrationAdjustments` 还记录左第1肋的显示范围校正：用右侧范围镜像到左关节原点，不改原生骨骼运动或力学参数。`build_anatomical_muscles.py` 可用已安装锁定依赖的环境从原图谱重建绑定资产。大网格异步载入，载入期间关节编辑仍可使用。

新全身 API 位于 `/api/fullbody/model`、`/pose`、`/rotate`、`/grasp`、`/solve`，姿势编辑与动作求解分别使用独立的原生工作进程，其他页面的肌力计算不会占住编辑进程。`/rotate` 接收拖动起点 `q`、关节 `joint`、冻结的世界旋转轴 `axis`、累计角度 `angleDelta`、所选源轴 `coordinate` 及 `mode`。页面默认使用 `source-joint` 并直接传所选原生轴，保留固定耦合；`strict-plane` 为接口缺省模式，由界面传相机法向。响应 `rotation` 包含接受状态、原因、作用范围及耦合引起的沿请求轴位移；只有请求轴为相机法向时才代表视线深度。拒绝的请求不会覆盖页面上一张已接受的姿势。回归入口 `verify_local_rotation.py` 检查所有控制点的锚点、全部独立旋转坐标的修改范围、上游世界变换、严格平面与源耦合，以及历史无效姿势的修复规则。旧 `/ik`、`verify_ik.py` 和 `/api/body/*` 保留作兼容或对照，不用于新圆环操作。实验按模型 ID 分开保存于浏览器，也可导出 JSON；不同模型的姿势文件不会静默混用。详细环境与固定依赖版本见 [安装说明](RELEASE_ASSETS.md) 和 [依赖清单](candidates/runtime/requirements-lock.txt)。

动作 API 新增 `groundEnabled` 布尔字段及 `support: "free"`。旧动作未写地面字段时，仅足底支撑模式推断为有地面；显式无地面不能搭配足底支撑。每帧 `groundCheck` 报告穿地，`gravity` 报告重力，`anatomy` 报告关节与身体保护检查。运行 `verify_ground.py` 复核地面开关不重复加重力、负重、足底反力、无支撑静止及身体穿地正反例。

## 为什么不能直接用“700”代表全身已覆盖

原始 primary 入口只有 85 个标量关节。虽然包含 700 条肌腱路径，其中 192 条附着在相同刚性关节链上，长度不会随任何内部运动改变，因而不能产生运动力矩。它们包括 152 条肋间肌束、22 条胸段多裂肌束、12 条腰段多裂肌束和 6 条腹内斜肌束。原始双手也没有手指关节。

源文件中保留了腹部 3 个、四节腰椎 12 个、十一节胸椎 33 个以及 24 根肋骨的 72 个关节参数，只是将它们注释。恢复这些原始参数后，192 条恒长路径都有了相对运动。右手使用源 manipulation 版本；左手沿用源左侧骨骼、附着点及肌腱路径，保留原有左臂关节，并按右手镜像补入 22 个手部关节。每侧新增 20 个手内在肌执行单元，总数从 700 增为 740。原有手腕与手指肌肉按详细版本替换，没有重复计算。

## 独立数值检查

从仓库根目录运行命令。

```powershell
& ./.venv-fullbody/Scripts/python.exe -X utf8 experiments/body-lab/fullbody_verify.py
```

发行时生成的 `fullbody-coverage.json` 记录每个独立坐标对应的肌腱单元，`fullbody-validation.json` 保存该版模型哈希、测试姿态与实际误差。下列历史数值来自 v3 的原生检查。

- v3确定性姿态检查中，740条路径全部具有非零耦合力臂；201个内部独立坐标全部有肌肉作用。整体位置和方向的6个坐标没有内部肌肉力矩，这是预期结果。
- 对全部740条肌腱长度和207个独立坐标做中心差分，与原生力臂乘解析投影对照，v3最大误差约 `3.47e-10 m/rad`（平移坐标为m/m）。
- 对总质量和质心的重力势能做中心差分，与原生重力项对照，v3最大误差约 `8.11e-8 N/N·m`。
- 检查不同姿态和激活水平下的原生主动、被动张力边界。肌肉处于无法提供主动张力的长度时保留零容量，不用标称最大力代替。
- 在固定激活水平下改变各区域姿态，检查真实肌腱长度和张力随之变化。这验证肌肉本构响应，不代表已经从动作唯一推断出人体真实招募策略。
- 原生逆动力学与质量矩阵方程对照；左手镜像与右手在对称姿态下的20对手内在肌长度及张力对照。

**v3已重新通过中立姿态与受控持物姿态的完整系统配力检查。** 这需要明确计入原关节达到原始界限时的单向止挡反力：下限只能阻止继续减小，上限只能阻止继续增大，内部自由位置不能借用止挡。中立姿态无止挡时仍不可行，结果保留在报告中。止挡反力单列为 `jointLimitTorques`，不计为肌肉张力；全部201个内部坐标仍须满足平衡，新增膝内外旋不获得理想止挡力。

此修正针对一个已复现的上游问题。原始 manipulation 入口和校准前扩展模型的多条骨间肌路径短于给定长度范围，主动容量为零。例如 `1stPI` 当前路径约0.051 m，源范围为0.085–0.116 m。现在沿同一几何和源关节范围搜索长度极值，得到约0.0462–0.0528 m，保持最大力、附着点、路径和归一化肌肉参数不变；中立姿态的主动容量恢复为约37.82 N。共14条肌肉发生这种范围修正。

[校准记录](candidates/runtime/hand-range-calibration.json)保存原始与派生范围、极值姿态、两个固定随机种子的有界搜索方法及模型哈希。官方原生长度范围模拟未收敛，未采用其输出；最终方法是原生肌腱几何上的有界优化。独立验证在完整模型复现所有极值，额外抽取每条肌肉30组姿态检查范围，并核对只有具名长度范围改变；绝对资源路径改为相对路径时，验证它们仍指向同一文件。这是几何估计，不是对肌纤维最优长度、肌腱松弛长度或完整伸肌腱膜的测量和重建。

旧校准前后对照保留在历史报告：校准前中立姿态有止挡和无止挡均不可行。当前v3另外重跑了合法止挡下的完整配力，实际残差见当前验证报告。不能通过放宽容差、加入任意理想关节力矩或修改标称最大力来替代这一检查。旧模型与验证结果分别保存在 `expanded-before-range-calibration.xml` 和 `candidates/audit/fullbody-validation-before-range-calibration.json`。

两个实验台页面和新旧模型接口可以读取：新模型740个单元、旧全身模型80个单元、原肘部模型6个单元。超限姿态请求若遇服务正在计算返回429，验证将其记为待重试；收到422才算通过输入范围检查。可在上方命令末尾添加 `--api-url http://127.0.0.1:4192` 一并复核。

v3生产求解链也已重新核查：实际 `solve_frame.rawTorques` 与完整质量矩阵、速度偏置及加速度对照，包含源模型的关节附加惯量；手持握点的加速度差分与外载力矩虚功检查通过。加入真实握持接触后，受控负重实验使用同一闭合手指和肘零位比较0与2 kg；当前精确值见验证报告。旧的张手75°持物数值属于掌心点载荷历史结果，不再作为握持正确的证据。另有0→90°屈肘、保持并返回的85帧2 kg持物回归，不能据此认为任意姿势都能配平。

50 kg超出能力的动作、悬空脚承担足底支撑的动作均被判为不可行。所有帧保留原来的骨架姿态，停用肌力和激活显示；随后重新求解可行的2 kg动作能够恢复。浏览器的真实编辑与回放由界面验收另行记录；脚本的生产检查直接调用与服务相同的求解器。数值一致性不等同人体逐肌张力真值或临床验证。

## 实际浏览器求解与当前限制

当前左右斜方肌横部已接入源网格附着区、连续表面形变和骨体积避让。其余四类已知问题仍见[逐项动画核查](http://127.0.0.1:4193/)。

本轮历史界面与资产验收记录分别记录96个关节入口、代表性实际操作、器械握持、正式表面资产及固定案例回放，范围与未解决项见[全身审计](WHOLEBODY_AUDIT.md)。此前双膝专项检查已原样归档至旧膝专项记录，包括真实鼠标拖环、三关键帧预览、旧版草稿兼容，以及当时计算版本的37帧膝旋转配力；不把该历史结果重新标记为本轮计算代码验证。

**下面整表是v2历史浏览器演示结果，不计为v3整段动作已通过。** 原始记录仍见历史求解页面摘要。本轮没有重跑表内全部长动作，后续使用应按当前模型重新求解。

| 页面演示 | 实际帧数／动作时长 | 求解结果 |
|---|---:|---|
| 拇指活动 | 109帧／9秒 | 全部740个单元参与，全部帧可行，最大平衡残差约`1.95e-14 Nm` |
| 四指张开 | 109帧／9秒 | 全部帧可行，最大残差约`2.09e-14 Nm` |
| 躯干活动 | 61帧／5秒 | 全部帧可行，最大残差约`1.26e-9 Nm` |
| 手持5 kg抬举 | 73帧／6秒 | 全部帧可行，最大残差约`8.94e-13 Nm` |
| 联合屈指反例 | 61帧／5秒 | 59帧不可行，整段肌力停用，姿势仍可回放 |
| 足底支撑深蹲反例 | 85帧／7秒 | 67帧不满足接触条件，整段肌力停用；最大足底滑移约16.4 cm |

当前模型仍保留这些建模限制：手部有五指运动和肌肉计算，但联合屈指序列仍可能不可行，14条长度范围校准没有补建完整伸肌腱膜。器械已接入手部胶囊接触与摩擦配力，但尚未重建皮肤接触面积、完整伸肌腱膜、接触弹性及滑落动力学，因此接触力与肌肉张力仍是指定模型下的估计。

配力采用每帧独立的最小激活总和优化。肌肉存在多种满足同一关节力矩的分配，优化可能在相邻帧切换分配，造成张力跳变；当前没有额外激活动力学、跨帧平滑或实测共同收缩约束。这些限制需要结合动作及输出解释，不能把曲线当作唯一的人体真实用力方式。

## 候选比较与使用条款

另一个候选 MuscleMimic 的完整 XML 有 416 个执行单元，双手可动，但头颈关节在整身入口中被注释，缺少这里需要的颈部和肋骨覆盖。它包含 122 个标量关节和一个六自由度根关节、51 条耦合约束；README 所写的 72 需要与“独立关节数”和物理自由度区分。源码已在 `candidates/audit/mm416/` 留存，未纳入当前运行模型。

MuscleMimic 顶层为 Apache-2.0，但其 NOTICE 明确上游 MoBL-ARMS 模型定义有非商业限制。MS-Human-700 当前分发许可证为 Apache-2.0；未来如果商业再分发，还需沿上游来源核对模型定义和网格各自条款，不能根据顶层文件推断全部上游权利。当前交付是本地研究实验。

计算代码的验证版本由 `computationSha256` 标识，并与模型文件哈希一起匹配报告和预检动作。编辑与求解工作进程在执行前后核对源码，浏览器核对请求/回复版本；运行中修改计算源码后应重启服务并刷新页面，不沿用旧结果。
